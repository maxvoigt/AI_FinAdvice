# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Framework

This is an **oTree** experiment (Python-based behavioral research platform). Each app is a directory with `__init__.py` (models + pages) and `.html` templates.

## Commands

```bash
# Development server (localhost:8000)
otree devserver

# Reset database (required after changing models)
otree resetdb

# Production (via Procfile)
otree prodserver1of2   # web process
otree prodserver2of2   # worker process
```

Set `OTREE_ADMIN_PASSWORD` environment variable before running. Admin UI is at `/admin/`.

## Experiment Structure

The single session `finAdvice` runs three apps in sequence:

1. **`welcome`** — Prolific ID entry, Google reCaptcha, three attention checks (fruit letter recall, reading comprehension, audio word recall)
2. **`demographics_before`** — Demographics survey, incentivized trust game (strategy method), attitude scales (general trust, algo aversion, risk tolerance, patience)
3. **`investmentGame`** — Task explanation, comprehension questions, attention check, then the investment task (10 observation rounds + 15 investment rounds across 5 assets)

## Treatment Assignment

Assigned in `welcome/creating_session` based on `participant.id_in_session`:
- `treatment = (id - 1) % 4` — four treatments: 0 = human participant, 1 = financial advisor, 2-3 = AI/ChatGPT
- `priceChart = floor((id - 1) / 4)` — indexes into the pre-generated asset price CSV (1000 rows)

Treatment and priceChart are stored on `participant` fields so they persist across apps.

## Asset Data

Asset prices are generated by `returnSimulation.m` (MATLAB) using a binary return model calibrated from Ebert (2015):
- **`_static/global/assetPrices.csv`** — 1000 rows × 125 columns (5 assets × 25 price points each, starting at 100)
- **`_static/global/assetParameters.csv`** — 4 rows × 3 columns (probIncrease, priceIncrease, priceDecrease)

Investment Option 5 is perfectly negatively correlated with Option 1 (same parameters, reversed outcomes).

Each participant gets columns `[0:25]`, `[25:50]`, `[50:75]`, `[75:100]`, `[100:125]` from their assigned `priceChart` row.

## Frontend

- `_static/js/compr_modules.js` — Bundled React components used on the comprehension questions page (`compQuestions`). This file is pre-compiled; do not assume a build step exists.
- Templates pass data via `vars_for_template` (server-side) and `js_vars` (exposed as `js_vars` in templates for JavaScript access).
- `live_method` on pages handles real-time client-server communication (reCaptcha validation, attention check submission, investment period tracking).

## Architecture Principle (Strictly Enforced)

**Front-end templates must contain no logic.** All business logic belongs in Python (`__init__.py`):
- Computations, conditionals, and data transformations → `vars_for_template` or `js_vars`
- Validation and state changes → `before_next_page`, `error_message`, or `live_method`
- Templates only render values passed from the server; they must not compute, derive, or decide anything themselves

## Testing Mode

`SESSION_CONFIG_DEFAULTS` has `testing=True`. Templates receive this flag and use it to pre-fill or skip fields during development. Set to `False` for production runs.

## Key Participant Fields

Stored on `participant` (persist across apps): `treatment`, `priceChart`, `investmentOption1Prices` through `investmentOption5Prices` (Python lists of floats).

## Treatment-Specific Behavior

- **`compQ_4`** (advice source question) is only included in `compQuestions` for treatments 1–3 (not control treatment 0), via `get_form_fields`.
- **Trust game** (`demographics_before/trustGame`) shows a different `partner_type` string per treatment: "another participant" (0), "a financial advisor" (1), or "a generative AI system, such as ChatGPT" (2–3).

## Investment Holdings Storage

`investmentGame/Player` stores holdings as JSON-encoded strings (`StringField`, e.g. `investmentOption1Holdings = "[]"`). Use `ast.literal_eval` to parse them back to lists.

## Attention Checks Detail

- **`welcome`**: Three checks (fruit letter recall, reading comprehension, audio word recall). `attentionCheck_Results` is only displayed if `all_attention_checks` is `False`.
- **`investmentGame/atnQuest`**: Uses fuzzy Levenshtein matching (distance ≤ 2) against the target phrase `"i read the explanation"`. Result stored in `attention_check_correct`.

## reCaptcha Keys

Keys are hardcoded in `settings.py` for development. For production, switch to the commented-out `environ.get(...)` pattern in that file.
